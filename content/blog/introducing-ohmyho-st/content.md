# Introduction to ohmyho.st

By [Sebastian Mertens](https://www.linkedin.com/in/auto-mate/) · Published September 13, 2026 · Updated November 1, 2026

Bring a GitHub app and ask your agent to deploy it. ohmyho.st gives your coding agent the CLI, MCP tools, and task  skills needded to review the project, connect to the repository, and prepare a deployment that you can review.

Registration is open; no invitation or access code is required. Copy the agent prommpt from the home page. Your agent  will send you a sign-up link that you can use to log in or create an account. Once you're connected, tell your agent which app you want to deploy.

For  exammple:

```text
Check my GitHub app and prepare an ohmyho.st Dev deployment. Identify the services it needs, check its main flows and give me the preview URL. Explain anything I need to review before publishing to Prod, and preserve any existing production data.
```

## Test your app before you publish it

Open the preview and test out the features that people will use. A public Vite app may not need a database or a login provider. An app with a  database must be tested with its migrations and real data flows. If it has accounts, forms, or uploads, test those as well before asking your agent to publsih it.

Your projects share an organizational credit balance. You can ask your agent which project used credits, whether a domain is ready, or what a deployment  is waiting for. Shared project notes help ensure a seamless transition during the next agent session. The [cost comparison for five side projects](/blog/what-vercel-supabase-resend-cost-for-five-side-projects) explains the shared balance compared to separtae subscriptions with Vercel, Supabase, and Resend.

The documentation describes the currently available stup methods. Start by using the app you already have, and then test  the deployment before sending people there.
