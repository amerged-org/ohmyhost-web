## Static Astro Hosting or Server-Side Rendering?

| Rendering Mode | What it's intended for | What ohmyho.st Offers |
| --- | --- | --- |
| Static Astro-Site | Blogs, documentation, portfolios, and marketing pages that are updated upon publication | HTML, CSS, images, and browser scripts generated by the Astro build |
| Astro SSR | Pages or endpoints that read the current request | A Cloudflare Worker built using the official Astro adapter, as well as public assets |
| SSR with pre-rendered pages | An app with public content and dynamic routes | Static output for pre-rendered routes and a worker for routes at the time of the request |

An interactive React component does not require the entire site to use SSR. Astro can render the page during  the build and hydrate the component in the browser. Use server-side rendering if the response requires inofrmation from the request.

Keep your existing rendering mode when you switch hosts. The deployment check verifies your Astro configuration and lock file before the build and then reports the supported rutnime as  well as any specific blockers.

## How to host an Astro website

Use an existing GitHub connection or a managed source project. Your agent can ceck out a local copy and continue working on the project that is already associated with  this workspace.

1. **Test the application.** Check the  Atsro rendering mode, the source connection, dependencies, and required services.
2. **Build a Dev preview.** Prepare a deploymment plan for  this specific source version, and then build it in Dev.
3. **Test the site.** Open nested pages, images , feeds, and brwser interactions. For SSR, test dynamic routes and API endpoints.
4. **Deploy  the tested version.** Promote the tested dev artifact to Production without rebuilding, and then connnect or test your own domain.

## Astro-SSR Compatibility and Limitations

SSR uses the official Cloudflare adapter  and requires Worker-compatible server dependencies. A package that runs in Node during the build proess may require a different implementation at the time of the request.

Use the default Astro source and output directories. Disable native KV sessions and use image passthrough for SSR. Additional, customer-defined Cloudflare binddings, provider cache , and Cloudflare Images are outside the scope of this integration. The [Astro Deployment Guide](https://docs.ohmyho.st/frameworks/astro) lists the exact configuration.

Your application can keep its existing authentication provider. Optional database , file, and email integrations folllow their own supported runtime contracts. Check which integration you are actually using before you publish.

## Questions About Astro Hosting

### Is Astro free to use?

Yes. The Astro framework is free and open source under the [MIT License](https://github.com/withastro/astro/blob/main/LICENSE). Hosting is a separate service: ohmyho.st starts with free credits, and builds , hosting, and optional services use up that credit baalnce. The [pricing page](/pricing) explains the hosting costs.

### Can I host a static astronomy website without a database?

Yes. Publish the generated HTML and assets. Only add a database if the application neds one; a blog or portfolio can read all of its content during  the build.

### Is Astro only for static websites?

No. Astro supports static output and server-side rendering. On ohmyho.st , request-driven pages, middleware, and API endpoints run on Cloudflare Workers using the official Asrto adapter. Pre-rendered routes remain static, and client-side islands can be interactive in both modes.

### Can I choose EU hosting for an Astro project?

Yes. When creating the project , select the EU project region. New projects deploy theeir databases, new files, and builds in this region. Existing projects that have been moved to the U.S. with the owner’s consent use U.S. databases; recorded R2 object locations remain unchanged. The actual database location is returned by database_compute_get. The Customer API cannot change the region of an existing project. Static assets are served through Cloudflare’s global delivery network, while transactional emals  are processed in the U.S. The [Hosting Region Guide](https://docs.ohmyho.st/environments#choose-a-hosting-region-once) explains the scope.

### Can I test an Astro deployment before it's released?

Yes. First, build and test the Dev environment , and then promote that exact artifact to Production. That way, the tested application bytes will match the version your vissitors receive.
